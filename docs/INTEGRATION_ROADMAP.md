## 🏗️ Архитектура интеграции

### Концепция
Smart Areometr становится **интеллектуальным датчиком** в экосистеме самогонной автоматики, предоставляя:
- Real-time данные о крепости
- Управление разделением на фракции
- Автоматическое переключение приемников
- Интеграцию с системами контроля температуры и управления

### Топология системы


### Протоколы коммуникации

#### 1. MQTT (приоритет #1)
**Топики для публикации:**
```
distillery/areometer/state         # Общее состояние
distillery/areometer/alcohol       # Крепость (%)
distillery/areometer/temperature   # Температура (°C)
distillery/areometer/stability     # Стабильность сигнала (%)
distillery/areometer/fraction      # Текущая фракция (head/body/tail)
```

**Топики для подписки:**
```
distillery/control/calibrate       # Команда калибровки
distillery/control/set_thresholds  # Настройка порогов фракций
distillery/control/reset           # Сброс
```

#### 2. REST API (уже реализовано)
Текущий API расширяется для автоматики:
```
GET  /api/distillation/state       # Состояние процесса
POST /api/distillation/start       # Старт мониторинга
POST /api/distillation/stop        # Стоп
GET  /api/distillation/fractions   # Статистика по фракциям
```

#### 3. I2C/UART (для локальной связи)
Возможность подключения к мастер-контроллеру напрямую:
- I2C адрес: 0x48 (стандарт для датчиков)
- UART: 115200 baud, протокол JSON
- CAN bus (опционально, для промышленных систем)

## 📖 Сценарии использования

### Сценарий 1: Базовая интеграция (MVP)
```
[Самогонный аппарат] → [Smart Areometr] → [MQTT] → [Home Assistant]
                                              ↓
                                        [Telegram уведомления]
```

**Процесс:**
1. Ареометр постоянно измеряет крепость
2. Публикует данные в MQTT каждые 5 секунд
3. Home Assistant строит графики и хранит историю
4. При смене фракции отправляет уведомление в Telegram
5. Пользователь вручную переключает приемники

### Сценарий 2: Полуавтоматическая система
```
[Аппарат] → [Ареометр] → [MQTT] → [Контроллер автоматики]
                            ↓              ↓
                    [Home Assistant] [Сервоприводы клапанов]
```

**Процесс:**
1. Ареометр определяет фракцию
2. Отправляет команду контроллеру через MQTT
3. Контроллер управляет клапанами
4. Автоматическое разделение на емкости
5. Пользователь мониторит через Home Assistant

### Сценарий 3: Полностью автоматическая перегонка
```
[Аппарат с ТЭНом] → [Мастер-контроллер] ← [Ареометр]
                            ↓                   ↓
                    [Управление нагревом]  [MQTT Cloud]
                    [Управление охлаждением]    ↓
                    [Клапаны]              [Мобильное приложение]
```

**Процесс:**
1. Запуск процесса через мобильное приложение
2. Мастер-контроллер управляет нагревом
3. Ареометр непрерывно мониторит крепость
4. При достижении порогов - автоматическое переключение
5. Контроль температуры для стабилизации
6. Полная телеметрия в облако
7. Push-уведомления о завершении этапов

### Конфигурация (config.h расширение)

```cpp
// === MQTT Configuration ===
#define MQTT_ENABLED true
#define MQTT_SERVER "192.168.1.100"
#define MQTT_PORT 1883
#define MQTT_USER "distillery"
#define MQTT_PASSWORD "secret"
#define MQTT_CLIENT_ID "smart-areometr-01"

// Топики
#define MQTT_TOPIC_STATE "distillery/areometer/state"
#define MQTT_TOPIC_ALCOHOL "distillery/areometer/alcohol"
#define MQTT_TOPIC_TEMP "distillery/areometer/temperature"
#define MQTT_TOPIC_FRACTION "distillery/areometer/fraction"

// === Fraction Detection ===
#define FRACTION_HEAD_THRESHOLD 85.0f    // Головы >85%
#define FRACTION_BODY_MIN 78.0f          // Тело 78-85%
#define FRACTION_BODY_MAX 85.0f
#define FRACTION_TAIL_THRESHOLD 78.0f    // Хвосты <78%

// Скорость изменения (% в минуту)
#define FRACTION_RATE_THRESHOLD 0.5f

// === Receiver Control ===
#define RECEIVER_COUNT 3
#define RECEIVER_1_PIN GPIO_NUM_5
#define RECEIVER_2_PIN GPIO_NUM_6
#define RECEIVER_3_PIN GPIO_NUM_7
#define SERVO_ANGLE_MIN 0
#define SERVO_ANGLE_MAX 180

// === Distillation Session ===
#define SESSION_LOG_INTERVAL 5000        // Логировать каждые 5 секунд
#define SESSION_MAX_DURATION 14400000    // Макс. 4 часа (мс)
```

## 💡 Заметки по архитектуре

### Принципы проектирования:
1. **Модульность** - каждая фича в отдельном классе
2. **Обратная совместимость** - старые API сохраняются
3. **Конфигурируемость** - все через веб-интерфейс или config.h
4. **Отказоустойчивость** - работа при потере связи с MQTT
5. **Расширяемость** - легко добавить новые протоколы

### Обработка ошибок:
- Автоматическое переподключение к MQTT
- Локальное кеширование данных при потере сети
- Watchdog timer для защиты от зависаний
- Резервное сохранение калибровки в EEPROM

### Оптимизация производительности:
- Публикация в MQTT только при изменении данных
- Агрегация измерений (среднее за период)
- Приоритеты задач (RTOS tasks)
- Экономия энергии (deep sleep между измерениями)
