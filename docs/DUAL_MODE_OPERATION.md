# 🎛️ Dual Mode Operation - Двухрежимная работа

## Обзор

Smart Areometr поддерживает два режима работы для разных типов перегонки:

1. **🌾 Mash Mode (Из браги)** - автоматическое определение фракций
2. **📊 Monitoring Mode (Мониторинг)** - только телеметрия без авто-детекции

---

## Зачем нужны два режима?

### Проблема

Детекция фракций по абсолютному значению крепости **работает** только для первой перегонки из браги:
- ✅ **Первая перегонка** (брага → спирт-сырец): крепость меняется 95% → 85% → 78% → 50%
- ❌ **Вторая перегонка** (ректификация): крепость постоянна ~92-96% весь процесс

При ректификации фракции определяются **по времени и объёму**, а не по крепости.

### Решение

Два отдельных режима с разной логикой работы:

| Режим | Детекция | MQTT | Графики | Статистика |
|-------|----------|------|---------|------------|
| Mash Mode | ✅ Авто | ✅ Да | ✅ Да | ✅ Да |
| Monitoring Mode | ❌ Нет | ✅ Да | ✅ Да | ✅ Да |

---

## Mash Mode (Из браги)

**Применение:** Первая перегонка из браги

### Как работает

1. **Автоматическое определение фракций** по крепости:
   - **Foreshots** (первач): первые 50 мл
   - **Heads** (головы): крепость > 85%
   - **Body** (тело): крепость 78-85%
   - **Tails** (хвосты): крепость < 78%
   - **Finished** (завершено): крепость < 5%

2. **MQTT события** при смене фракций:
```json
{
  "event": "fraction_change",
  "from": "heads",
  "to": "body",
  "alcohol": 82.5,
  "temperature": 20.3,
  "timestamp": 1234567890
}
```

3. **Автоматика реагирует** на события и переключает клапаны

### Настройка порогов

Все пороги настраиваются через веб-интерфейс:

```
🔴 Первач (Foreshots)
- Объем: 30-50 мл (по умолчанию 50 мл)

🟠 Головы (Heads)
- Порог крепости: 85-90% (по умолчанию 85%)

🟢 Тело (Body)
- Минимум: 78%
- Максимум: 85%

🟡 Хвосты (Tails)
- Порог крепости: 75-80% (по умолчанию 78%)
- Скорость падения: >0.5 %/мин
```

### Пример процесса

```
Старт → Foreshots (50 мл) → Heads (95% → 85%) → Body (85% → 78%) → Tails (78% → 40%) → Finished
```

## Monitoring Mode (Мониторинг)

**Применение:**
- Вторая перегонка (ректификация)
- Любые процессы с постоянной крепостью
- Просто мониторинг без управления

### Как работает

1. **Нет автоматической детекции** фракций
2. **Только сбор данных**:
   - Крепость (%)
   - Температура (°C)
   - Скорость изменения крепости (%/мин)
   - Стабильность сигнала (%)
3. **Полная телеметрия через MQTT**
4. **Графики в реальном времени**
5. **Ручное управление** фракциями (если нужно)

### MQTT топики

Даже в режиме мониторинга публикуются все данные:

```bash
# Полное состояние (каждые 5 сек)
distillery/areometer/state

# Отдельные показатели
distillery/areometer/alcohol         # Крепость
distillery/areometer/temperature     # Температура
distillery/areometer/stability       # Стабильность
```

### Когда использовать

- ✅ **Ректификация** - крепость постоянна, фракции по времени
- ✅ **Контроль качества** - просто смотрим крепость
- ✅ **Эксперименты** - нужны только графики
- ✅ **Сторонняя автоматика** - детекция на контроллере

## Звуковые уведомления

### Функция

Звуковой сигнал при **резком падении крепости** - важный индикатор смены фракции.

### Настройки

- **Включить/выключить** - checkbox в веб-интерфейсе
- **Порог скорости падения** - по умолчанию 1.0 %/мин

### Когда срабатывает

```
Крепость падает быстрее 1.0 %/мин → 3 коротких бипа (800 Hz)
```

### Примеры

```
✅ Heads → Body:    крепость 85% → 82% за 1 минуту = -3.0 %/мин → СИГНАЛ
✅ Body → Tails:    крепость 80% → 75% за 2 минуты = -2.5 %/мин → СИГНАЛ
❌ Стабильно:       крепость 82% → 81.5% за 5 минут = -0.1 %/мин → тихо
```

### Защита от ложных срабатываний

- Минимум **10 секунд** между сигналами
- Срабатывает только при **падении** (не росте)
- Порог настраиваемый

Установить режим работы

```json
{
  "mode": "mash"
```

```json

  "status": "success"
```

## Интеграция

### Home Assistant

```yaml
automation:
  # Уведомление о быстром падении крепости
  - alias: "Alert on rapid alcohol drop"
    trigger:
      platform: mqtt
      topic: "distillery/areometer/state"
    condition:
      - condition: template

            Скорость: {{ trigger.payload_json.alcohol_rate }} %/мин
            Текущая: {{ trigger.payload_json.alcohol }}%
```

### Python

```python

def on_message(client, userdata, msg):
    data = json.loads(msg.payload)

    # Проверка на резкое падение
    if 'alcohol_rate' in data:
        rate = data['alcohol_rate']
        if rate < -1.0:  # Падение быстрее 1 %/мин
            print(f"⚠️ ALERT: Rapid drop {rate} %/min")
            # Отправить уведомление, логировать и т.д.

client = mqtt.Client()
client.on_message = on_message
client.connect("192.168.1.100", 1883)
client.subscribe("distillery/areometer/state")
client.loop_forever()
```

## Переключение между режимами

### Во время перегонки

**Можно переключать в любой момент:**

```
Mash Mode → Monitoring Mode
- Детекция останавливается
- Текущая фракция фиксируется
- Продолжается сбор телеметрии

Monitoring Mode → Mash Mode
- Детекция включается
- Начинается с текущей фракции
- Или с UNKNOWN если не было фракции
```

### Между сессиями

**Режим сохраняется между перезагрузками:**
- Настройки хранятся в JSON на устройстве
- После перезагрузки - восстанавливается последний режим

## FAQ

### В каком режиме начать?

- **Первая перегонка из браги?** → Mash Mode
- **Ректификация / вторая перегонка?** → Monitoring Mode
- **Не уверен?** → Попробуй Mash Mode, переключишь если нужно

### Можно ли переключиться во время работы?

✅ **Да, можно в любой момент** - данные не потеряются

### Будет ли работать MQTT в обоих режимах?

✅ **Да**, телеметрия работает всегда. Разница только в событиях `fraction_change`.

### Зачем Monitoring Mode если есть MQTT?

- Ректификация: крепость постоянна ~95%, детекция не работает
- Мониторинг: иногда нужны только графики без автоматики
- Гибкость: можно использовать устройство для разных задач

### Как звук работает в браузере?

- Web Audio API генерирует звук (не нужны файлы)
- Работает во всех современных браузерах
- Требует первого клика для инициализации (безопасность)

## Примеры использования

### Сценарий 1: Классическая перегонка из браги

```
1. Открываем веб-интерфейс
2. Выбираем "🌾 Mash Mode"
3. Настраиваем пороги (или оставляем по умолчанию)
4. Включаем звуковые уведомления (порог 1.0 %/мин)
5. Жмём "Сохранить настройки"
6. Начинаем перегонку
7. Устройство автоматически определяет фракции
8. При смене фракции → звук + MQTT событие
9. Автоматика переключает клапаны
```

### Сценарий 2: Ректификация

```
1. Открываем веб-интерфейс
2. Выбираем "📊 Monitoring Mode"
3. Настраиваем звуковые уведомления (порог 0.5 %/мин)
4. Жмём "Сохранить настройки"
5. Начинаем ректификацию
6. Крепость постоянна ~95% - авто-детекция не работает
7. Следим за графиками в реальном времени
8. MQTT публикует все данные для сторонней автоматики
9. Если крепость резко упадёт → звуковой сигнал
```

### Сценарий 3: Экспериментальная перегонка

```
1. Выбираем "📊 Monitoring Mode"
2. Запускаем перегонку с новыми параметрами
3. Следим за телеметрией и графиками
4. Записываем данные через MQTT в InfluxDB
5. Анализируем в Grafana
6. На основе анализа - корректируем пороги для Mash Mode
```

## Технические детали

### Код (C++)

```cpp
// Установка режима
fractionDetector.setMode(DetectionMode::MASH_MODE);
// или
fractionDetector.setMode(DetectionMode::MONITORING_MODE);

// Проверка режима
if (fractionDetector.getMode() == DetectionMode::MASH_MODE) {
    // Авто-детекция активна
}
```

### Логика в update()

```cpp
Fraction FractionDetector::update(float alcohol, float temperature) {
    // Всегда собираем данные
    addToHistory(alcohol);
    updateStats(alcohol);
    updateVolume();

    // Только в Mash Mode - детектируем фракции
    if (mode == DetectionMode::MONITORING_MODE) {
        return currentFraction;  // Не меняем фракцию
    }

    // Детекция фракций (только Mash Mode)
    Fraction newFraction = detectFraction(alcohol);
    if (newFraction != currentFraction) {
        onFractionChange(newFraction);  // → MQTT event
    }

    return newFraction;
}
```

## Обновления и миграция

### Обновление с предыдущей версии

Если у вас уже установлен Smart Areometr без поддержки режимов:

1. **Прошивка обновляется через OTA**
2. **По умолчанию включается Mash Mode** (совместимость)
3. **Все настройки сохраняются**

```json

{
  "foreshots_volume": 50,
```

## Заключение

Двухрежимная система делает Smart Areometr **универсальным** инструментом:

✅ **Mash Mode** - полная автоматика для первой перегонки
✅ **Monitoring Mode** - гибкий мониторинг для ректификации
✅ **Звуковые уведомления** - не пропустите важные моменты
✅ **MQTT интеграция** - работает в обоих режимах

Выбирайте режим в зависимости от задачи и наслаждайтесь процессом! 🍺
